## Risks identified

- School repository: not the access needed to require pull requests or forbid pushing to `main`,
  hence working on a mirror repository.
- Technologies not decided yet: to be decided on 2 September.
- Tickets not distributed yet: the sprint only really starts after the meeting of the next day.

## Decisions

- Availability: daily at 4 pm on Wednesday and Thursday, sprint review on Friday at 2:30 pm.
- Repository created as a mirror of the school one, to be able to use pull requests and protect
  `main`.
- Administrator access to the repository and to the GitHub organisation for everyone.
- Git conventions agreed: branches, conventional commits, pull requests with review, no push to
  `main`.
- Rotation of the Scrum Masters set for the following weeks.
- First version of the backlog validated.
- By the next day, everyone reviews the tickets of the GitHub Project and the existing code, and
  thinks about the technologies to choose.
- On 2 September: a shared debrief to refine the tickets and the tasks, then distribution according
  to the strengths and wishes of each person across the different areas
  ([kickoff meeting](../decisions/2026-09-02-reunion-de-lancement.md)).
