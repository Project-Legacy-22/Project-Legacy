Poser les bases du projet : organisation de l'équipe, choix des technologies, dépôt et conventions

## Risques identifiés

- Dépôt de l'école : pas les accès nécessaires pour imposer les pull requests ni interdire le push
  sur `main`, d'où un travail sur un dépôt miroir.
- Technologies pas encore tranchées : à décider le 2 septembre.
- Tickets pas encore répartis : le sprint ne démarre réellement qu'après le point du lendemain.

## Décisions

- Disponibilités : daily à 16 h les mercredi et jeudi, revue de sprint le vendredi à 14 h 30.
- Dépôt créé en miroir de celui de l'école, pour pouvoir utiliser les pull requests et protéger
  `main`.
- Accès administrateur au dépôt et à l'organisation GitHub pour tous.
- Conventions Git actées : branches, commits conventionnels, pull requests avec relecture, pas de
  push sur `main`.
- Tour de rôle des Scrum Masters fixé pour les semaines suivantes.
- Première version du backlog validée.
- D'ici le lendemain, chacun relit les tickets du GitHub Project et le code existant, et réfléchit
  aux technologies à retenir.
- Le 2 septembre : compte rendu commun pour affiner les tickets et les tâches, puis répartition
  selon les facilités et les envies de chacun sur les différents domaines
  ([réunion de lancement](../decisions/2026-09-02-reunion-de-lancement.md)).
